How it works, for engineers
  1. In the browser. The page loads an 8-bit ONNX build of my fine-tuned DistilBERT model (about 65 MB, cached) and runs it with transformers.js. Nothing you type is sent anywhere.
  2. Model, then rules. The model tags spans in overlapping 128-token windows; checksum and format rules (Luhn, SSN, IBAN, IP) confirm number-shaped finds and stretch partial ones to full length.
  3. Reversible. In the 60-second demo, Prompt Shield swaps each value for a placeholder like <PERSON_1>, keeps the key only in page memory, and puts the real values back into the AI's answer locally.
  4. Same engine everywhere. The Python package (pip install scrubpii), a logging filter, a GitHub Action and a browser extension share the model and rules. How it's measured →

FREE TOOL · RUNS IN YOUR BROWSER

SAML & SCIM Debugger

Paste a broken SSO sign-in and it shows exactly where it failed and which setting fixes it.

It decodes SAML, verifies the XML signature with code I wrote from the W3C specs, and catches expired assertions, audience and ACS mismatches and signature wrapping. It checks SCIM against RFC 7643/7644 and Entra ID and Okta quirks, runs eight real attacks against your response, acts as a test identity provider and exports redacted reports for tickets. No libraries.

Enterprise SSO and user provisioning

C#/.NETSAML 2.0JWTSCIMEntra IDNUnit
Problem

Enterprise customers needed their people to sign in with their own identity provider, and every onboarding meant hours of manual developer work to set up users.

What I did

CASE STUDY · PRIVACY

Privacy request automation

C#PythonAWS ECSEventBridgeCloudFormationSalesforceAlloyDB
Problem

Each request to remove someone's personal data took about 2 hours by hand. Separately, privacy opt-outs in Salesforce had to be reconciled with the privacy database by an engineer and someone from legal.

What I did

Built a C# privacy microservice that owns intake, processing and the confirmation that no requester data remains. Built a containerized Python service on ECS that syncs Salesforce with the AlloyDB (PostgreSQL) privacy database every day, with idempotent batch writes, plus the CloudFormation for scheduling, metrics, alarms and dashboards, deployed by GitHub Actions.

Impact
  • 50+ removal requests a day handled with no manual work
  • About 12 hours a week of engineering and legal reconciliation gone
  • Zero redundant API writes

CASE STUDY · PERFORMANCE & RELIABILITY

Faster, steadier production services

DapperSQL ServerCloudWatchSentryGitHub ActionsNode.js
Problem

Blocking database calls and SQL Server parameter sniffing slowed services down, timeouts set off cascading retry storms, and releases could quietly go stale in one environment.

What I did

Replaced blocking ADO.NET calls with async Dapper and fixed the parameter sniffing.   • Retry storms on 408 and 504 timeouts stopped

  • Mentored four interns, two hired full-time
