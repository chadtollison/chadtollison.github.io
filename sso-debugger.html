        How it works
        
        
        
          
        01
        Decode
        It undoes whatever wrapped the message: URL encoding, Base64, and the DEFLATE compression the redirect binding uses. Then it reads the XML with the browser's own parser and refuses DOCTYPEs.
        
          
        02
        Verify
        The XML signature check is written from the W3C specs: exclusive canonicalization, digest, then the RSA or ECDSA signature through WebCrypto. It agrees with the xml-crypto library on every signing style I tested, including Entra ID's.
        
          
        03
        Check
        Rules come from the SAML 2.0 Web SSO profile and SCIM's RFC 7643 and 7644, plus the real-world quirks of Entra ID and Okta, and attacks like signature wrapping and comment injection.
        
        
        
        
        The examples are signed live in your browser with a demo key that is published in this page's code on purpose, so no real system trusts it. This is a debugging aid, not a security audit: your SP library should still do its own validation.
