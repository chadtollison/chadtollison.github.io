How I beat Microsoft Presidio

Presidio is the open-source default for finding personal data in text. I built scrubpii to do the same job better, smaller and fully offline. Here is what moved the score, what didn't, and how I kept the test fair.

The short version
  • Better data beat a bigger model. A newer, larger model fully hid 52% of personal data. The small one hid 99%.
  • The model proposes, math confirms. Checksums for cards, SSNs, IBANs and IPs fix what a model can't be sure of.
  • Long documents needed a different reading window, which lifted the hardest test by 11 points.
  • Shipping small mattered as much as accuracy: 8-bit ONNX cut the install from 1.5 GB to 288 MB with no loss.
  • I score strictly. An item only counts if 90% of it is hidden, because half a phone number still leaks.
01

The scoreboard

Ten test sets in five languages: emails, chat logs, support tickets, medical notes, server logs and financial documents. Every set is held-out test data the model never trained on, and the finance set comes from a source it never saw at all. The score is the strict one: how much personal data actually ends up hidden.

02

How I kept score

Beating a tool on your own test is easy. I wanted a test Presidio's authors would accept. So the scoring ignores labels and asks one question: would this text be safe to share? If Presidio calls an address a LOCATION and I call it an ADDRESS, both get full credit.

FULLY HIDDEN

Share of real personal-data items with at least 90% of their characters redacted. The headline number.

WAS PERSONAL

Share of finds that landed on real personal data. This catches a tool that redacts everything.

CAUGHT

Share of items that a find touches at all. Lenient: one character counts.

F1

Combines caught and was personal. Lenient for the same reason, so it's never the headline.

Why the strict score leads. My first charts led with F1. A review showed why that's not enough: a broken detector that marks one character of each email scores a perfect F1, while fully hidden correctly shows zero. scrubpii wins on both, but only fully hidden proves the redaction is safe, so every chart here uses it. It also keeps the tool honest about precision: 99% of scrubpii's finds on English were personal data, against 91% for Presidio.

Both tools see the same texts on the same machine, the sets come from public datasets with their own answer keys, and the scoring code is public, so anyone can rerun it.

03

What moved the number

I tracked every change against the hardest set: financial documents from a source the model never trained on. Long, dense and full of numbers that look personal but aren't. During development I tracked F1, so this chart uses it; the final version fully hides 78% of items here against Presidio's 56%.

  1. Real data beat clever data

    Version 2 learned from sentences I generated. Version 3 trained on 500,000 realistic examples from ai4privacy (CC BY 4.0) and jumped to 0.99 F1 on English. But the finance score dropped, from 0.70 to 0.65. That dip told me the next problem wasn't the data.

  2. Long documents needed a shorter window

    The model trained on short texts, then read long reports in 512-token chunks and lost track of what mattered. Reading in overlapping 128-token windows, the length it learned on, took finance from 0.65 to 0.76 without retraining.

  3. The model proposes, math confirms

    A model can guess that 16 digits are a card number. A Luhn checksum knows. I added validators for cards, SSNs, IBANs, IPs and real US area codes. They confirm or reject the model's finds and stretch a half-found item to its full length. Each find carries a reason, like model found it, rule confirmed: valid Luhn checksum, so a privacy reviewer can audit every redaction.

  4. The bigger model lost

    I tried DeBERTa-v3, a newer and larger model that usually wins on paper. It fully hid 52% of English personal data against 99% for the small DistilBERT model, and ran about 2.5 times slower. I kept the small one. Measuring before switching saved me from shipping a worse product that sounded better.

  5. Shipping small mattered as much as accuracy

    Nobody adds a 1.5 GB dependency to strip emails from logs. Exporting to ONNX with 8-bit weights removed PyTorch entirely. F1 moved from 0.993 to 0.992.

  6. Broader data, then stop

    Version 5 added NVIDIA's Nemotron-PII set (medical notes, tickets, logs) plus French, German and Italian. German now fully hides 97% of personal data, and unseen finance rose to 0.845 F1 even though no finance data was added.

04

Where Presidio misses

On the English set, the gap is almost all in things a regex can't describe: names, addresses, phone numbers in odd formats and ID numbers. On emails, both are perfect.

05

Where it still loses

SSNs and passports

Presidio fully hid every SSN and passport number in the English set. scrubpii hid 94% and 96%. Those are small groups, 18 and 24 items, but a miss is a miss.

Finance isn't solved

78% beats 56%, but one in five items in unfamiliar financial paperwork isn't fully hidden. That's the next thing to fix.

The plug-in has limits

If you already run Presidio, scrubpii.presidio.add_to(analyzer) lifts it from 67% to 99.7% fully hidden on English. Its precision stays lower than scrubpii alone, because Presidio's own false alarms stay.
