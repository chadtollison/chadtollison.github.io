scrubpii.

Find and redact personal data with one line of Python. A fine-tuned transformer finds names, emails, phones, IDs, cards, addresses, keys and more, in English and Spanish, and checksum rules double-check it. Everything runs on your machine.

"Hi, I'm [PERSON]. Email [EMAIL] or call [PHONE]."

Redaction modes

from scrubpii import redact, tokenize, restore

text = "Call Sarah Johnson at 662-634-1142."
redact(text)                 # Call [PERSON] at [PHONE].
redact(text, mode="mask")    # Call █████████████ at ████████████.
redact(text, mode="fake")    # Call Avery Brooks at (202) 555-0117.

safe, key = tokenize(text)   # Call <PERSON_1> at <PHONE_1>.
restore(safe, key) == text   # True

Fake values are harmless on purpose. Phones use the 555-01xx range reserved for fiction, cards are public test numbers, IPs come from the documentation range, and SSNs start with 9, which is never issued. Use find(text) to get each item's type, position, confidence, and the rule that confirmed it.

Your own rules, in plain English

Tell it what else to hide in a sentence. No regex and no AI service: scrubpii reads the rule itself, offline. In a shape, # is a digit and @ a letter; everything else is matched as written. Try rules in the demo.

from scrubpii import teach, redact, understand

teach("redact any ###-#####-##-RC as an RC code",
      "hide codes like AB-1234 as order number",
      'redact 8 digit numbers after "member" as member id',
      "redact Globex and Initech as client",
      "never redact support@acme.com")

redact("Ref 123-45678-90-RC for Globex, member 12345678")
# Ref [RC_CODE] for [CLIENT], member [MEMBER_ID]
understand("redact any ###-#####-##-RC as an RC code")
# Redact 3 digits, then "-", then 5 digits, then "-", then 2 digits, then "-RC", labeled [RC_CODE]

Every redaction can also be explained: audit(text) lists each item, how sure it was, what found it and why, plus what it left visible, without storing the personal data itself.

JSON, CSV and pandas

These collect every string and run the model in batches, so they're much faster than a loop.

from scrubpii import redact_many, redact_json, redact_csv, redact_dataframe

redact_many(["Call Sarah at 6626341142", "Email raj@example.com"])
redact_json({"user": {"name": "Sarah Johnson", "email": "sarah.j@example.com", "age": 41}})
# {"user": {"name": "[PERSON]", "email": "[EMAIL]", "age": 41}}
redact_csv(open("customers.csv").read(), columns=["name", "email", "notes"], mode="token")
safe_df = redact_dataframe(df, mode="fake")     # pip install "scrubpii[pandas]"

Keep personal data out of LLM prompts

Scrub prompts before they reach a hosted model, then put the real values back into its reply. One key covers the whole conversation, so the same person stays <PERSON_1> in every turn.

from scrubpii import Guard

guard = Guard()
safe = guard.scrub("Write to Sarah Johnson (sarah.j@example.com) about her refund")
# "Write to <PERSON_1> (<EMAIL_1>) about her refund"   <- all the LLM sees
reply = call_your_llm(safe)
guard.restore(reply)                       # real names back in

ask = guard.wrap(call_your_llm)            # or wrap the call once
scrub, unscrub = guard.langchain()         # LangChain: scrub | prompt | llm | parser | unscrub

HTTP API

pip install "scrubpii[server]"
scrubpii serve --port 8000

curl -X POST localhost:8000/redact -H 'content-type: application/json' \
     -d '{"text": "Call Sarah at 6626341142", "mode": "token"}'

The endpoints are POST /redact, POST /find, POST /restore and GET /health, with interactive docs at /docs.

Command line

scrubpii "Call Sarah at 662-634-1142"
cat notes.txt | scrubpii --mode mask > notes-safe.txt
scrubpii --file customers.csv --columns name,email -o customers-safe.csv   # .csv .json .jsonl .txt
scrubpii --find "My SSN is 123-45-6789"

Privacy

scrubpii downloads its model once from Hugging Face and caches it. After that, nothing you redact goes anywhere. Set HF_HUB_OFFLINE=1 to make sure no network call is even attempted. The browser demo runs the same model on your device with ONNX Runtime.

Training data credits: ai4privacy open-pii-masking-500k (CC BY 4.0) and Gretel PII masking (Apache 2.0), plus generated data.

This is a research model, so it can miss things or flag things by mistake. Please don't rely on it alone for compliance work.
